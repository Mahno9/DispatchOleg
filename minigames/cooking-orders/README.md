# cooking-orders — готовка для персонажей

К окну выдачи кухонного терминала выстраивается очередь супергероев. Игрок читает рецепт,
по шагам добавляет ингредиенты (дозируемые — удержанием), затем варит блюдо в котле,
удерживая указатель нужное время по кольцевой шкале. Ошибка — блюдо испорчено и заказ
начинается заново; три ошибки — «ВСЁ СГОРЕЛО» и вся смена с начала.

Спецификация — `docs/minigames/06-cooking-orders.md`, контракт — `minigame_contract.md`.
Чистый DOM + CSS, SVG только для кольцевой шкалы. Логика заказа — в `src/engine.ts`
(без DOM и таймеров), тесты — `src/engine.test.ts`.

## Управление

Один указатель, pointer-события (мышь, тач, стилус). Клавиатура не требуется.

| Тип шага | Действие |
|---|---|
| Дозируемый (`amount > 0`) | Нажать и **удерживать** ячейку ингредиента. Уровень растёт со скоростью `fillRatePerSec`; отпустить внутри янтарной зоны шкалы. Перелив за верх шкалы — мгновенная ошибка. |
| Простой (`amount = 0`) | Одиночный клик по ячейке. Результат — на отпускании, над той же ячейкой. |
| Варка | Когда все ингредиенты добавлены, полка гаснет, котёл получает подпись `ЗАЖМИ`. Удерживать котёл; кольцо заполняется, отпустить внутри янтарного сектора. |

`setPointerCapture` ставится на удерживаемый элемент, `pointerup`/`pointercancel` слушаются на `window`.
`blur`, `visibilitychange` и провал кадра rAF дольше 500 мс отменяют удержание **без пенальти** —
показывается бирюзовая плашка `ПРЕРВАНО — ПОВТОРИ ШАГ`, шаг остаётся текущим.

## Настройки (`schema.json`)

| Поле | Дефолт | Описание |
|---|---|---|
| `ingredients[]` | 8 шт. | `id` (kebab-case, уникален), `name`, `image` (`asset:image`), `unitName` |
| `characters[]` | 3 шт. | `name`, `portrait` (`asset:image`), `orderName`, `cookSeconds`, `steps[]` |
| `characters[].steps[]` | — | `ingredientId` (ссылка на `ingredients[].id`), `amount` (`0` = положить кликом) |
| `fillRatePerSec` | `1.5` | Скорость наполнения, единиц в секунду |
| `doseTolerancePct` | `40` | Полуширина янтарной зоны в долях **одной** единицы (не от `amount`) |
| `cookTolerancePct` | `12` | Полуширина янтарного сектора кольца, % от `cookSeconds` |
| `failsAllowed` | `3` | Ошибок до «ВСЁ СГОРЕЛО» |
| `pointsPerStep` / `pointsPerOrder` | `10` / `50` | Очки |
| `spoilAnimationMs` | `1000` | Длительность анимации испорченной еды |
| `sounds.*` | — | `place`, `pourLoop`, `pourOk`, `cookLoop`, `orderDone`, `fail`, `wipe` — `asset:audio` |

Изображения ингредиентов и портреты по умолчанию пустые: игра рисует инлайновые контурные
SVG-плейсхолдеры (глиф выбирается по `id`, для портрета — силуэт с первой буквой имени).
Админ может загрузить свои ассеты, ничего больше менять не нужно.

Пустой `characters[]` или шаг со ссылкой на несуществующий `ingredientId` — рендерится панель
ошибки конфигурации, `onComplete` **не** вызывается (выход остаётся за платформой, кнопка `ВЫЙТИ` → `onExit()`).

## Очки

`+pointsPerStep` за верный шаг, `+pointsPerOrder` за выданный заказ.
Ошибка снимает очки за шаги **текущего** заказа (`orderScore`) и откатывает его на шаг 1;
очки за выданные заказы не трогаются. «ВСЁ СГОРЕЛО» обнуляет счёт и начинает смену заново.
Идеальный прогон дефолтного контента: `11 × 10 + 3 × 50 = 260`.

## Завершение

Игра завершается только победой: все заказы выданы → `onComplete({ score, won: true, details })`.
Проигрыша нет — «ВСЁ СГОРЕЛО» перезапускает смену внутри сессии; выйти можно только
платформенной кнопкой `ВЫЙТИ` (`onExit()`).

## `details` в `onComplete`

| Ключ | Значение |
|---|---|
| `orders` | Сколько заказов в смене |
| `fails` | Ошибок за последнюю (успешную) смену |
| `wipes` | Сколько раз всё сгорело за сессию |
| `styleTag` | `flawless` (`wipes = 0`, `fails = 0`), `steady` (`wipes = 0`, были ошибки), `scorched` (`wipes ≥ 1`) |

## Прогресс

`onProgress('ЗАКАЗ 2/3 · ШАГ 3/4', percent)` при смене шага, заказа и ошибке —
`percent` считается по всем шагам всех заказов, включая шаг варки (для дефолтного контента 14).
При вайпе — `onProgress('ВСЁ СГОРЕЛО · СМЕНА С НАЧАЛА', 0)`.
