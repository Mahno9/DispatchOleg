# task-sort — сортировка задач диспетчера

Диспетчер принимает смену: стопка входящих тикетов падает на стол. Свои активные задачи надо выстроить
в **ОЧЕРЕДЬ** по срочности (сверху — самое срочное), чужие и уже выполненные — отправить в **АРХИВ**.
Приоритет живёт в подвале карточки рядом с номером тикета, но по умолчанию заштрихован. Наведение
(или фокус с клавиатуры) запускает «запрос»: 500–1200 мс спиннера, потом метка `P1`…`P4`. Уход курсора
до конца обрывает запрос; загруженный приоритет остаётся на карточке до конца смены.

Спецификация — `docs/minigames/03-task-sort.md`, контракт — `minigame_contract.md`.

## Управление

- Перетаскивание карточек между зонами и внутри очереди — pointer events (мышь, тач, стилус).
- Дублирующие кнопки на каждой карточке: `→` в очередь, `⌦` в архив, `←` во входящие, `▲` / `▼` — порядок.
- Клавиатура: карточка достижима табом, `Alt+↑` / `Alt+↓` меняют её место в очереди.
- `ПОДТВЕРДИТЬ СМЕНУ` активна только когда ВХОДЯЩИЕ пусты.

## Настройки (`schema.json`)

| Поле | Дефолт | Описание |
|---|---|---|
| `playerName` | `{player}` | Имя диспетчера; эталон для сравнения с `assignee`. `{player}` — подставится имя игрока (docs/platform.md §3.4) |
| `attempts` | `2` | Сколько раз можно подтвердить смену |
| `tasks[]` | 30 задач | `text`, `assignee` (`{player}`/`Марина`/`Тимур`), `done`, `priority` (1 — срочный) |
| `music` | — | Фоновая петля на всю смену (`asset:audio`, поле **верхнего уровня**). Играет подложкой: ползунок музыки домножается на `0.35`, чтобы фон не перекрывал щелчки карточек |
| `sounds.*` | — | `deal` (раскладка стопки), `pick`, `drop`, `shred`, `probe` / `probeDone` (запрос приоритета и его получение), `ready` (входящие разобраны), `scan` (проверка раскладки), `error`, `confirm` — `asset:audio` |

Пустой (или полностью невалидный) `tasks` — рендерится панель `КОНФИГ ПУСТ · ЗАДАЧИ НЕ ЗАГРУЖЕНЫ`
с кнопкой `ЗАВЕРШИТЬ`, вызывается `onExit()`, `onComplete` не вызывается.

## Очки

`+10` за верно размещённую карточку, `+5` за каждую верно упорядоченную пару в очереди.
`maxScore = 10 × N + 5 × C(K, 2)`, где `K` — число своих активных задач (для дефолтного контента 630).
Штрафов нет; число попыток на очки не влияет — считается финальная раскладка.

## Финал смены

Поражения в игре нет: task-sort — финал смены, игрок её закрывает в любом случае.
`onComplete` всегда получает `won: true` (контракт: «если в игре нет понятия поражение —
передавай `won: true`»). Попытки сохраняются как механика правки ошибок: после неудачной
проверки отмеченные карточки можно переложить, а на последней попытке смена закрывается
с тем, что получилось. Снятое поле `winThresholdPercent` больше не читается — в старых
уровнях оно молча игнорируется.

## `details` в `onComplete`

| Ключ | Значение |
|---|---|
| `mistakes` | Всего ошибок |
| `archivedOwnActive` | Своих активных задач отправлено в архив |
| `queuedForeignOrDone` | Чужих или выполненных задач в очереди |
| `orderInversions` | Инвертированных пар в очереди |
| `attemptsUsed` | Сколько попыток потрачено |
| `percent` | `round(score / maxScore × 100)` |
| `styleTag` | `flawless` (идеально с первой), `corrected` (идеально со второй), `sloppy` (закрыто с ошибками) |

## Прогресс

`onProgress('РАЗОБРАНО: X / Y', percent)` при каждом изменении числа входящих;
после неудачной проверки — `ИСПРАВЬТЕ ОТМЕЧЕННОЕ · ПОПЫТКА 2 ИЗ 2` без процента;
в финале — `СМЕНА ЗАКРЫТА` или `СМЕНА ЗАКРЫТА · ОШИБОК N`, 100 %.
