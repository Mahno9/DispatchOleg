# tetris-fill — заполнение силуэта

Админ рисует силуэт на сетке, движок при запуске сам разбивает его на тетромино и роняет детали
сверху по одной. Игрок двигает и вращает падающую деталь, чтобы она встала ровно на своё место:
у каждой детали ровно одно правильное место, совпало — деталь фиксируется, легла мимо — рассыпается
и подаётся заново.

Спецификация — `docs/minigames/07-tetris-fill.md`, контракт — `minigame_contract.md`.

## Управление

Игра рассчитана на телефон: под полем — панель из четырёх кнопок, клавиатура работает параллельно.

| Действие | Кнопка | Клавиша |
|---|---|---|
| Сдвиг влево / вправо | `◀` `▶` (автоповтор ~120 мс при удержании) | `←` / `→` |
| Поворот на 90° CW | `↻` | `↑`, `R` или `К` |
| Мягкий спуск (ускорение) | удержание `⤓` дольше 250 мс | удержание `↓` |
| Мгновенный сброс | короткое нажатие `⤓` | `Пробел` |

Зеркалирования нет — только 4 ориентации. Тень под деталью показывает, куда она приземлится.

- **Совпало** — деталь фиксируется мгновенно, даже если могла бы падать дальше (магнитная фиксация).
- **Легла мимо** — через `lockDelayMs` рассыпается, `errors++`, та же деталь подаётся заново в той же
  ориентации. Удачный сдвиг сбрасывает таймер фиксации — можно поправить деталь на весу.

## Настройки (`schema.json`)

| Поле | Дефолт | Описание |
|---|---|---|
| `shape` | 4×4 «плюс» | `{width, height, rows}`, `#` — клетка силуэта, `.` — пусто. Виджет `grid-paint` |
| `scoreThresholds[]` | 300/150/0 | Кривая баллов по времени (`curve`) |
| `errorPenalty` | `5` | Штраф за одну ошибочную попытку |
| `hintAfterErrors` | `3` | После скольких суммарных ошибок включается призрак-подсказка (`0` — сразу) |
| `randomizeRotation` | `true` | Выдавать деталь в случайной из 4 ориентаций |
| `fallIntervalMs` | `700` | Сколько мс деталь проводит на одной строке (150…3000) |
| `softDropFactor` | `6` | Во сколько раз быстрее падение при мягком спуске (1…20) |
| `lockDelayMs` | `500` | Сколько деталь лежит не на своём месте до рассыпания (0…2000) |
| `spawnColumn` | `center` | Где появляется деталь: `center` или `target` («над своим местом», проще) |
| `sounds.*` | — | `rotate`, `place`, `error`, `hint`, `win` — `asset:audio` |

Ограничения силуэта: `1 ≤ width,height ≤ 16`, число `#` — от 1 до 60. Несвязные фигуры, дырки и
фигуры из 1–2 клеток валидны. Пустой (или невалидный по формату) силуэт — панель
`ОШИБКА КОНФИГУРАЦИИ` и `onExit()`; `onComplete` не вызывается.

## Почему силуэт всегда решаем

Два правила закрывают все тупики:

1. **Магнитная фиксация.** Каждый кадр *до* проверки столкновений: если абсолютные клетки детали
   равны её месту — фиксируем. Без этого `['###','...','###']` непроходим: верхняя полоса легла бы
   на нижнюю и никогда не дошла бы до своей строки.
2. **Гравитационный порядок подачи** (`orderForGravity`). Топологическая сортировка: A подаётся
   раньше B, если есть колонка, где клетка A строго **ниже** клетки B. Ничьи разрешаются прежним
   порядком по якорю, поэтому силуэт по-прежнему заполняется снизу вверх. Без этого деталь можно
   похоронить под уже уложенной (репро: `['##','##','.#']`).

Дальше проходимость следует автоматически: деталь появляется целиком над строкой 0 (с запасом на
самую высокую из 4 ориентаций), где ничего не заперто, — её можно свободно повернуть и подвести к
любой колонке; а порядок подачи гарантирует, что ни одна зафиксированная клетка не окажется выше
клеток текущего места.

## Очки

```
score = max(0, round(scoreForElapsed(scoreThresholds, elapsedSeconds)) − errorPenalty × errors)
```

Поражения нет: `won` всегда `true`, игра заканчивается только заполненным силуэтом.

## `details` в `onComplete`

| Ключ | Значение |
|---|---|
| `errors` | Число рассыпавшихся деталей |
| `pieces` | Сколько деталей было в разбиении |
| `elapsedSeconds` | Затраченное время, целых секунд |
| `styleTag` | `precise` — без единой ошибки, `rough` — с ошибками |

## Разбиение

`partition()` — детерминированный backtracking с branch-and-bound: якорь всегда нижняя-левая
непокрытая клетка, размеры деталей перебираются 4 → 1, отсечение по сумме `ceil(|компонента| / 4)`,
ранний выход при достижении `ceil(N / 4)` деталей. Результат прогоняется через `orderForGravity()`,
которая и даёт порядок подачи. Одинаковый силуэт всегда даёт одно и то же разбиение и один и тот же
порядок. Разбиение не хранится в конфиге — пересчитывается при каждом `init` и в превью виджета
`grid-paint` в админке (там лежит копия обоих алгоритмов, номера деталей в превью совпадают с игрой).
