# Ревью диалогов: от названия до коммита

Вход — название игры («Восточный мост»), id диалога или описание сцены («провал Феномачо»). Выход — закоммиченные правки в `content/dialogues/` и БД. Между ними обязательная остановка на ревью человеком.

## 1. Подготовка

1. Загрузить скиллы `dialogue-writing` и `joke-engineering`, прочитать `Lore/lore-dispatcher-full.md` целиком. Черновик сохраняется в `artifacts/`, куда его класть — не спрашивать (см. п. 4).
2. Найти диалоги. БД `data/app.sqlite` — источник истины, читать из неё:

```bash
node -e "
const db=new (require('better-sqlite3'))('data/app.sqlite',{readonly:true});
const q=process.argv[1].toLowerCase();
for(const g of db.prepare('select * from games').all().filter(g=>g.title.toLowerCase().includes(q)))
  console.log('игра',g.id,g.title,'·',g.minigame_id,'· персонаж',g.character_id,'· до',g.pre_dialogue_id,'· победа',g.post_win_dialogue_id,'· провал',g.post_lose_dialogue_id,'· стиль',g.style_dialogues_json);
for(const d of db.prepare('select id,title from dialogues').all().filter(d=>d.title.toLowerCase().includes(q)))
  console.log('диалог',d.id,d.title);" "<часть названия>"
```

   По описанию сцены искать по тексту реплик. Несколько кандидатов — показать их и спросить.
3. Прочитать реплики из БД и сверить с `content/` (это же команда финальной проверки в п. 6):

```bash
node -e "
const db=new (require('better-sqlite3'))('data/app.sqlite',{readonly:true});const fs=require('fs');
for(const id of process.argv.slice(1)){
  const r=db.prepare('select title,nodes_json from dialogues where id=?').get(id);const a=JSON.parse(r.nodes_json);
  const b=JSON.parse(fs.readFileSync('content/dialogues/'+id+'.json','utf8')).nodes_json;
  console.log('## '+id+' '+r.title+' · remote='+!!a.remote+' · '+(JSON.stringify(a)===JSON.stringify(b)?'БД = content':'РАСХОЖДЕНИЕ БД и content'));
  for(const [k,n] of Object.entries(a.nodes)){console.log(k,n.speaker,n.side,'→',n.next,':',n.text);for(const c of n.choices||[])console.log('   выбор →',c.next,':',c.text)}
}" <id> <id> ...
```

   `remote=true` означает, что разговор идёт по рации. Имена персонажей по id лежат в `content/characters.json`.

## 2. Факты, против которых сверяется каждая реплика

Сбор фактов можно отдать субагенту на быстрой модели.

- **Конфиг игры** (`games.config_json`): цели и количества (`rescueTarget`, число карточек по колонкам). Любое число в реплике должно совпадать с тем, что игрок видит на экране.
- **Экран мини-игры**: туториал в `web/player/src/game/tutorials.ts` и строки UI в `minigames/<minigame_id>/src/index.ts`. Реплика не должна повторять итоговый баннер и не должна объяснять механику, которую уже показал туториал.
- **Остальные сцены персонажа** по всем диалогам: голос, «ты»/«вы» пары, мизансцена, сквозные нити. Если реплика сюда же бросает семя, развязку проверить по более поздней сцене.
- **Порядок показа**: `games.sort_order`, этапы меты (`meta_stages`). Термин или гэг из лора, которого игрок к этой сцене ещё не видел, для игрока — тёмное место. Проверка: grep по `content/` и туториалам.

## 3. Анализ

Для каждого диалога сначала записать мизансцену (где стоит, через что говорит, что видит) и линию намерения (чего добивается, что не отдаёт) — по строке на участника. Затем пройти узлы подряд:

- четыре запрета и восемь пунктов линии намерения из `dialogue-writing`, эхо в том числе поперёк развилок;
- на каждой шутке — диагноз joke-engineering (H1 очевидно, H2 темно, H3 жидко, H4 разжёвано, H5 чужой голос, H6 раздуто) и проверка пересказом одной фразой;
- длина пути по каждой ветке.

Реплики, которые лор или скилл цитирует как эталон, не трогать без явной причины. В ответе прямо сказать, что оставлено и почему.

Типичные находки, на которые смотреть в первую очередь:

- число не совпадает с конфигом (12 спасённых при `rescueTarget: 18`) или спорит с соседним числом («подзадача за полдня», а «среднее шесть часов»);
- реплика противоречит карточке или тексту самой игры (Замзам называет «итогом квартала» то, что в игре лежит закрытой карточкой);
- реплика дублирует итоговый экран («Смена принята», «несоответствия») или туториал;
- в развилке новый ответ спорит со старой строкой (c1 «до первого прыжка» при n4 «люди прыгают»);
- термин из лора без опоры («реконструктор» во второй игре). Лечится самоописывающим словом и вопросом собеседника («почему ваша метка на карте повернула к дому?»), а не пояснением;
- «ты»/«вы» пары расходится с другими сценами;
- панчлайн стоит в середине реплики, после него идёт хвост.

## 4. Черновик на ревью

Черновик — это `artifacts/<тема>-<ГГГГММДД>/<тема>.md` (каталог в `.gitignore`) и рядом копия `<тема>.baseline.md`. Открыть через `code <файл>`. В облако не публиковать.

Структура файла:
- заголовок и одна строка о составе: какие диалоги и что с чем совпадает;
- **Мизансцена** и **Намерения** — общие или по сценам;
- по каждому диалогу `## <id> · до игры | победа | провал`, дальше строки узлов:
  - `n4 · Диспетчер: …`
  - `a2 · A · Феномачо: …`
  - блок `**Выбор:**` со строками `- выбор A → a1: …`
  - подзаголовки веток;
- запасные варианты — строками `> альт …`: в JSON они не переносятся.

В чат идёт по каждому диалогу таблица «узел | проблема | правка». Ошибки фактов (числа, противоречия, «ты»/«вы») — отдельным блоком первыми. В конце — что осталось вне нормы и почему (например, длина канонной ловушки). `content/` на этом шаге не трогать, ждать ответа.

## 5. Итерация

Автор правит md руками или отвечает в чате. Каждый заход начинается с `diff <тема>.baseline.md <тема>.md`: каждую изменённую реплику проверить по правилам, включая эхо с соседями по обе стороны развилки. Вопрос «что тут значит X» — объяснить замысел по лору, назвать, почему не читается, и предложить вариант. В md вносить только после согласия.

## 6. Внесение (после явного «вноси»)

1. Снять `diff` с базой, чтобы подхватить ручные правки автора. `альт`-строки не берутся, если автор их не выбрал.
2. Выполнить `npm run content:dump`, затем `git status --porcelain`. Чужие изменения показать и не трогать.
3. Правку JSON отдать субагенту на быстрой модели. Промпт должен содержать:
   - byte-exact тексты по узлам;
   - текст варианта в `choices` вместе с узлом, который его повторяет;
   - запрет трогать что-либо, кроме `text`;
   - запись через `JSON.stringify(obj, null, 2)` с тем же хвостовым переводом строки;
   - `npm run content:load` (он же гоняет `check:content`);
   - стоп-условие инвариантом: «после дампа `content/` совпадает с БД; файлы вне списка не трогать», а не ожидаемым дифом.
4. Проверить самому, не по отчёту субагента:
   - повторный `content:dump` не даёт изменений вне списка;
   - `git diff -U0` меняет только строки `"text"`;
   - команда из п. 1.3 показывает «БД = content», а тексты совпадают с черновиком.
5. Обновить `.baseline.md` под внесённое состояние.

## 7. Коммит

Только после явного подтверждения. Просьба «вноси и коммить» им считается.

- Перед коммитом ещё раз выполнить `content:dump`.
- В коммит идут только файлы `content/dialogues/` этой задачи, отдельно от кода.
- Сообщение: `content: правки диалогов «<игра>» — <суть в 3–5 словах>`, без `Co-Authored-By`.

В отчёте назвать хэш, что проверено (load, чтение из БД) и что не проверено: вид в плеере `?test=dialogue:<id>`.
